## 0. 一句话

把桌面端从单一的"审批弹窗"升级为 **agent-ssh 的完整运维控制台**：审批、历史审批、审计日志、连接与会话、设置五个功能区，全部经 operator 会话面驱动，安全纪律（K8-③ 秘密不进 JS、纯文本渲染、CSP 锁）全线延续。

## 1. 定位与原则

| 原则 | 含义 |
|---|---|
| 控制台即外壳 | 桌面应用 = Host 的宿主 + 唯一人工交互面（T-20 形态延续）；CLI/飞书面保持不变，三面共用同一队列状态机 |
| operator 面专属 | 五个功能区全部走 operator 会话（口令解锁后可用）；agent 令牌对新增 RPC 一律 FORBIDDEN（矩阵红线延续） |
| 数据不落 UI 层 | 审计/历史数据经 invoke 即取即渲染（textNode），不在 JS 全局留存；CSP 继续锁死远程内容 |
| Host 是唯一事实源 | UI 不自行读写文件；一切数据经 RPC（新增方法见 §4），desktop.json 仍为部署描述 |

### 2.1 审批（现功能增强）

- 从"单请求展示"升级为**待决队列流**（`approval.list` 驱动，推送增量更新）：多请求堆叠、每卡含 profile/类别/完整命令/指纹短形/倒计时；
- 破坏性类卡片内嵌校验码输入（现逻辑）；批准/拒绝即 `approval.decide`（face=desktop）；
- 队列空态显示"队列干净 + 下一个请求到达时 toast"。

### 2.2 历史审批（新）

- 已决定（批准/拒绝）与过期请求的流水列表：时间、profile、类别、命令（脱敏档可选）、决定人（`approver` 字段）、结果；
- 数据源：审批队列目录内已决/过期文件（决定后文件本就留存于队列目录）——新增 RPC **`approval.history`**（operator 面专用）分页返回，UI 按 profile/结果/时间过滤；
- 明示语义：这是"审批操作流水"，不是命令执行审计（后者在审计视图）。

### 2.3 审计日志（新）

- Host 审计 JSONL（`config.toml.audit.log`）的查看器：倒序时间线、过滤（profile/命令类别/decision/ruleId/时间范围）、关键词搜索、尾部跟随（tail）；
- 新增 RPC **`audit.query`**（分页+过滤，服务端读 JSONL）与 **`audit.stats`**（今日条数/拒绝数/审批数聚合）；**跨轮转文件策略**（评审建议采纳）：store.ts 的 rotateIfNeeded 会把超限主文件改名 .1 序号后移——查询枚举主文件+全部轮转序列并按时间归并，分页 cursor 采用（文件序号, 行号）二元组而非全局行号；
- 显示字段即审计记录字段（时间/profile/user/command/class/decision/ruleId/approver/duration）；敏感内容沿审计既有脱敏（服务端已脱敏后才出 RPC）；
- **安全边界**：审计属于操作员视角数据，operator 面可读、agent 面 FORBIDDEN（矩阵增行，红线测试补枚举）。

### 2.4 连接与会话（新）

- `list-connections` 深化视图：每 profile 的连接状态、活动会话/PTY 数、最近活动；
- 新增 RPC **`quota.snapshot`**（operator 面）：每 profile 当日命令用量/配额（内存态 CommandQuota 的只读投影）；
-PTY 会话列表可强关（复用既有 pty-close 语义，operator 授权下经 tool.call 走完整管线？——**否**：控制台直调 `approval.list` 同级的运维 RPC 不合适；PTY 强关走既有 `tool.call pty-close`（operator 会话允许 tool.call），审计自然留痕）。

### 2.5 设置（新）

| 设置项 | 机制 | 说明 |
|---|---|---|
| 开机自启 | autostart 插件 enable/disable（Rust 侧已装，UI 化） | 即时生效，写系统注册表/启动项 |
| 更换 operator 口令 | 新 RPC **`host.admin.changePassword`**（旧口令验证 → scrypt 新哈希 → Host 原子写回 config.toml，ACL 保持 0600） | 所有在途 operator 会话即刻失效（安全默认），需重新解锁 |
| 审批面状态 | `host.status` 聚合（新 RPC）：desktop 在线数 / im 连接态 / queue 目录 | 只读展示（面的启停仍由 config 决定，UI 不改配置语义） |
| **宿主接入**（Agent 识别与 MCP 配置） | 扫描本机各类型 Agent 宿主（omp / Claude Code / Cursor / opencode / Codex / Gemini CLI），一键写入/移除 agent-ssh 的 MCP 条目——详见 §2.6 | 消除"每接一个宿主翻一次文档"的部署最后一公里 |
| Host 管理 | 重启 Host / 打开日志（现托盘菜单项进 UI）+ 端口/构建版本只读展示 | desktop.json 只读展示（改部署=改文件，UI 不编辑——避免控制台变成第二个配置面） |
| 关于 | Host/控制台版本、协议版本 | — |

### 2.6 宿主接入（Agent 识别与一键配置 MCP server）

**扫描（识别）**：**Host TS 侧适配器**（src/agents/，评审裁决：执行侧归 Host——desktop.json/队列/审计的既有读写域在 Host，桌面只发 RPC，与「控制台即外壳」原则一致；且避免 TS/Rust 双实现重蹈 K6 覆辙）按各宿主的**安装指纹**探测本机安装态——目录/可执行文件存在即视为已安装（不做进程扫描，不碰运行中的宿主）：

| 宿主 | 安装指纹 | MCP 配置文件 | 格式要点 |
|---|---|---|---|
| omp（oh-my-pi） | `~/.omp/` 或 `~/.bun/bin/omp.exe` | `~/.omp/agent/mcp.json` | `mcpServers.{name}.command/args/env/enabled` |
| Claude Code | `~/.claude/` 或 `~/.claude.json` | `~/.claude.json`（全局 mcpServers 节） | `mcpServers.{name}.command/args/env/type:"stdio"` |
| Cursor | `~/.cursor/` | `~/.cursor/mcp.json` | 同 mcpServers 惯例 |
| opencode | `~/.config/opencode/` | 全局 `~/.config/opencode/opencode.json`；项目根 `opencode.json(c)` 另计 | `mcp.{name}.type:"local"` + `command:[...]` 数组合一 + `environment`（键名与他家居异） |
| Codex CLI | `~/.codex/` | `~/.codex/config.toml` | **TOML**：`[mcp_servers.{name}]` command/args/env |
| Gemini CLI | `~/.gemini/` | `~/.gemini/settings.json` | `mcpServers` 惯例 |
| 其他（未知宿主） | — | — | 只列出检测说明，不自动写（用户手配） |

**写入（一键接入）**——对第三方应用配置文件的修改是本功能的全部风险所在，纪律如下：

1. **结构化改写**：JSON.parse → upsert `agent-ssh` 条目 → stringify 写回；绝不文本级插桩；不触碰文件内其他任何条目（逐键比对，改动最小化）；TOML（Codex）用 TOML 解析器同纪律；
2. **写前自动备份**：`<file>.bak-agent-ssh-<时间戳>`，UI 显示备份路径，可一键还原；
3. **条目内容同源**：command/args/env 与 desktop.json 单一事实源生成（nodePath/hostEntry/port/token），令牌不出部署描述；
4. **幂等**：重复点"接入"= 更新既有条目（版本升级/端口变更后可一键刷新所有宿主）；
5. **写后校验**：回读解析 + 断言 agent-ssh 条目存在且 JSON 合法，失败即回滚备份；
6. **明示生效条件**："已写入。重启该宿主后生效"（宿主进程不热载 MCP 配置）；
7. **移除**：只删 `agent-ssh` 键（还原语义），其余内容不动。

**RPC 增量**（operator 面专用）：`agents.scan`（宿主清单：类型/安装指纹/配置路径/接入态）、`agents.configure`（写入+备份+校验，返回备份路径）、`agents.remove`。全部 agent 面FORBIDDEN（矩阵增行）。

**UI**：设置页"宿主接入"区块——[扫描本机] → 宿主卡片列表（已接入 ✓ 绿标 / 未接入 [一键接入] / 不支持自动接入的显示路径与格式说明）→ 写入后卡片翻绿 + 备份路径折叠显示。

**显式不做**：不修改宿主配置中的其他 MCP 条目；不做宿主进程发现/热重载触发；不对配置文件做格式重排美化（结构化写回的缩进规范化是副作用，备份兜底）。

**显式不做**：UI 编辑 config.toml 的 profile/策略（配置文件是 Host 机权威面，控制台编辑会造成双写源）；多语言；主题。

## 3. 交互与视觉基调

- 深色单主题延续（钛金系），等宽字体渲染命令/审计原文；
- 危险动作（拒绝、强关 PTY、更换口令、**宿主接入写入 agents.configure**——可写第三方宿主配置，评审建议采纳）二次确认；
- 全部列表虚拟化不做（个人数据量级），分页 50 条/页 + "加载更多"。

## 4. RPC 协议增量（operator 面专用，方法×凭据矩阵增行）

| 方法 | 语义 | 数据源 |
|---|---|---|
| `approval.history` | 已决/过期审批分页 | 队列目录 JSONL 文件 |
| `audit.query` / `audit.stats` | 审计过滤查询/聚合 | config.toml.audit.log（服务端脱敏后出） |
| `quota.snapshot` | 每 profile 当日配额用量 | CommandQuota 只读投影 |
| `host.status` | 审批面在线态 + 版本聚合 | Host 内存态 |
| `host.admin.changePassword` | 口令轮换（旧口令验证）；**审计专项 ruleId=`host-password-rotated`**（评审建议采纳：高危动作独立可检索）；所有在途 operator 会话即刻失效 | scrypt 重哈希 → 原子写回 config |
| `agents.scan` / `agents.configure` / `agents.remove` | 宿主识别与 MCP 条目写入/移除（§2.6） | 各宿主配置文件（备份+校验+回滚纪律） |

矩阵红线测试同步扩展：新方法 × {agent, 无凭据, 过期会话, 谎报 class} 全部 FORBIDDEN。

## 6. 风险与取舍

| 项 | 取舍 |
|---|---|
| 审计出口面扩大 | 审计本就脱敏且面向操作员；新增出口仅 operator 会话可读，矩阵钉死。风险增量=会话令牌盗用（同既有 operator 面，A9 出界声明不变） |
| changePassword 写回 config | Host 进程原子写（tmp+rename），ACL 0600 保持；写失败不破坏旧哈希 |
| UI 复杂度上升 | 无框架红线延续（原生 JS 多视图，`ui/` 按视图拆模块）；窗口放大但保持轻量（~10MB 级 exe 不变） |
| 历史审批的留存边界 | 队列文件含已决记录即历史——不做独立持久化（审批的法律级留痕在审计，历史视图只是便利面） |
| 宿主接入写第三方配置 | 结构化改写+自动备份+回读校验失败即回滚+只动 agent-ssh 键（§2.6 七条纪律）；格式重排副作用由备份兜底；写入对象是各宿主自己的用户级配置（用户域内，无越权面） |
