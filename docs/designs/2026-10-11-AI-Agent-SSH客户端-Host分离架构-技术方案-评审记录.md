## 2. 唯一规格级冲突（必须回文档，否则 T-19 无法验收）

### 🔴 帧上限 1MB 与既有大输出治理相撞（qa 实测 + 架构，双发现）

§3.1 规定单帧 1MB 超限断连。但：

- full-chain 步骤②实测：`commandMaxOutputBytes`(1MB) 截断后返回 **1,056,768 字节**，JSON 序列化膨胀后必然超帧 → 按规则断连（test/integration/full-chain.test.ts:87-88 代码注释原值）；
- `sftp-upload-file` 的 content 是整个文件内联进 tool args（file-tools.ts:50），>1MB 合法上传即断连。

根因：http.ts 的 1MB 是**入站请求体**上限，v2 搬入 TCP 帧时未限定方向、未定义出站大响应处理。

**须主人裁决三选一并写入 §3.1**：

| 选项 | 内容 |
|---|---|
| a | 帧上限提至 4MB（简单，但 DoS 面同步扩大） |
| b | 出站响应分块（协议 v0.2 加 chunk 语义，复杂） |
| c | maxOutputBytes 默认值下调至帧上限安全余量内 |

对应边界测试入 T-14：「最大合法工具响应（截断态 1,056,768B）过单帧」。
