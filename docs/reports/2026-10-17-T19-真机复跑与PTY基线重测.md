## 三、过程发现与更正（重要）

### 3.1 T-19 原 PTY 基线系无效证据（假测量），已作废

- **现象**：首轮复跑 PTY 各档仅 ~2KB/s 且 echo 往返超时；深查发现 `scripts/t19-smoke.mjs`（及首轮复跑脚本沿用的调用）给 pty 系工具传了错误参数——`pty-open {profile, command:'sh'}`（schema 必填 `name`）、`pty-write/pty-read {session}`（实为 `name`+`cursor`）。
- **机理**：MCP SDK zod 校验拒绝后返回错误文本 "Inval**id** arguments..."；旧脚本的正则 `(?:session|id)[=: ]+` 从错误文本里抓出垃圾会话名"arguments"，随后每档"读数"实为 60/120 次×~137 字符的**错误响应文本**累计——伪造出"3.5s/8220 字符"的假吞吐；断言过弱（只查非空）未拦住。
- **波及**：T-19 自报证据中"PTY 首字节 4-5ms·2000 行 2.2s（localhost）"同源无效，**作废**，以上表真机数字为准。
- **处置**：`t19-smoke.mjs` PTY 段已修复（name+cursor 链式读取+isError 严格断言）；T-19 台账补 amend 更正。

### 3.2 Host 审计落点为配置旁文件（非平台目录）

`host serve` 将审计写入 `${configPath}.audit.log`（src/host/cli.ts:72）。平台目录 `%LOCALAPPDATA%\ssh-mcp\audit.log` 为旧单体时代遗留（止于 10-12）。首轮审计核验扫错位置致误报；建议 HOST-RUNBOOK 后续补一句审计落点说明（非阻断）。

### 3.3 首轮其余三项失败均为脚本缺陷，非产品缺陷

echo 窗口太短（真机 shell 就绪 >1.2s）、forward-close id 正则抓错 token、审计扫描目录错误——v2 全部修正后通过。
